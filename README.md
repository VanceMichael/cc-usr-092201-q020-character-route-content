# 赛道汉字内容编排

维护汉字文化内容的来源、授权、赛道点位和发布版本，让亲子健走沿线的展签、路牌、
绘本、讲解稿与互动活动引用同一套经过审校与授权的内容。

## 它解决什么

同一汉字（如"走"）曾在展区、路牌、绘本与拓印活动中出现不同释义，临时改稿也无法
确认哪些物料已经印出。本产品把内容编排成一条可审计的链：

```
原始依据 → 内容版本（字形/释义/适龄表达/文物图像）→ 载体版本（钉版）→ 印刷批次 → 现场扫码
```

- **统一来源**：每个内容版本必须引用原始依据（著录、字书、图像档案），
  文字类内容经专家审校、文物图像经授权核验后才能发布；同一内容条目同一时刻
  只有一个当前版本。
- **版本钉版**：载体版本逐条钉死"哪个条目的哪个内容版本"，发布后内容与指纹
  不可变；改稿只能出新版本，旧版留档。
- **双闸门**：载体版本发布需同时具备专家审校记录与图像授权核验记录，
  缺一不可；图像授权还按载体类别核验范围（展陈印刷/出版物/互动活动/数字展示）。
- **精准召回**：错字更正、素材撤权、路线改变、现场替换时，沿引用链做影响分析，
  只召回受影响载体的可发库存；旧版留档但不能再发放。无障碍表达增补属于
  追加式变更，只升级指定载体，其余批次不受影响。
- **现场核对**：每个发布的载体版本签发二维码（载体版本号 + 内容指纹），
  现场扫码即可识别"当前有效 / 旧版留档 / 已召回 / 指纹不符 / 无法识别"。
- **点位预览**：策展人员按点位查看家庭实际看到的组合内容（字形、释义、
  适龄说明、文物图像与授权状态），可导出 HTML。
- **反馈闭环**：互动活动反馈挂在"活动载体版本 + 适龄表达版本"上，
  同组表达变体之间比较理解率，用证据决定保留哪种说法。

## 目录

- `route_content/` 领域核心
  - `model.py` 领域词汇、记录类型与内容指纹
  - `catalog.py` 编排资料仓储与引用完整性校验
  - `content_service.py` 内容版本、专家审校、图像授权
  - `carrier_service.py` 点位/载体、钉版、双闸门发布、印刷批次、扫码核对
  - `change_service.py` 影响分析与召回：更正/撤权/撤点/无障碍增补/现场替换
  - `preview_service.py` 点位与路线预览；`render_html.py` HTML 导出
  - `feedback_service.py` 参与反馈与理解度对比
  - `seed.py` "走"字赛道种子数据（虚构标识）
- `contracts/` 资料结构约定（`domain.schema.json` 概览约定，
  `orchestration.schema.json` 编排资料契约）
- `fixtures/domain.json` 领域概览样例（公开约定，保持不变）
- `demo.py` 端到端演示：统一来源 → 错字更正 → 撤权 → 撤点 → 无障碍增补 →
  现场替换 → 扫码核对 → 反馈对比，产出写入 `output/`
- `tests/` 领域规则测试

## 运行

```bash
python -m unittest        # 全部测试（含 fixtures/domain.json 公开约定校验）
python -m demo            # 全流程演示，输出 output/*.json 与点位预览 HTML
```

仅依赖 Python 3.11+ 标准库。

## 状态与事实

领域概览样例中的状态示例为 待编写 → 专家审校 → 待授权 → 已发布 → 需更换 → 已归档，
编排核心沿用同一词汇：内容版本与载体版本各自走这条链，印刷批次另有
待发放/发放中/已发完/已停发/已召回。所有样例使用虚构标识，不含真实个人资料、
馆藏编号、账号或连接凭据。
